# All 19 SARS template reports rebuilt to fixed-layout Letter pages, with unified compare naming and a pixel-diff batch mode (v1)

Every SARS *template* report now emits its reference's own US-Letter page box (`792x612` landscape or `612x792` portrait) via `@page{size:...;margin:0}` instead of reflowing to A4, and paginates to the reference's true page count. The work follows the pattern already set by `schools_rank.py`: bespoke per-report renderers for the ranked-schools, top-schools, best-students, subjects-rank and result-slip families, plus a shared *layout mechanism* (`generic_fixed.py`) that the four thin generic-family renderers (`wards_rank`, `district_performance`, `mock_mobility`, `subject_school_rank`) parameterise. Alongside the renderers, `pixel_diff.py` gains a `--all` batch mode so pixel comparison runs for every report, and `output/compare/` is reorganised into `conversion/`, `template/`, `pixel/` subfolders sharing one `<name> - page N` stem. `measure_all.py` reports 19/19 on both size and page count; `pixel_diff --all --template` runs all 19 with no dimension mismatch; `pytest` is 42 green and `sars verify` is 19/19 at 100% text similarity.

Watch for: (1) the generic-family style blocks are near-identical parameterisations of one `_base_sheet` — technically distinct per report but structurally the same lattice, a design tension against strict per-report independence though it does not funnel a shared *visual identity* (confirmed); (2) page-1 pixel visible-match ranges from 44% (Mock Mobility, Governments) to 90% (Subjectwise Best Students) and this is honestly surfaced as un-recovered captions / bespoke tints / extract gaps, not papered over (confirmed); (3) `top_schools.py` reconstructs block captions from level/variant because they are not in the schema — a genuine fidelity gap acknowledged in the module docstring (confirmed).

**Verdict**: APPROVED

## High-level view

The user's three demands are all met. Every report is fixed to the correct page size and count — `measure_all.py` prints 19/19 on both axes, verified by running it. Pixel-to-pixel comparison now runs for *every* report through `pixel_diff.py --all`, which prints one line per report and explicitly lists any that mismatch rather than silently skipping — answering "PIXEL TO PIXEL WHY SKIPPING OTHERS?". The confusing flat compare naming is gone: `conversion/`, `template/` and `pixel/` subfolders each use the identical `<name> - page N` stem (pixel appends ` - diff`/` - overlay`), so only the subfolder disambiguates the kind — answering "WHICH IS WHICH?".

The per-report-independence rule is largely honoured. `schools_rank`, `top_schools`, `subjects_rank`, `best_students`, `best_students_subjectwise` and `school_result_slip` each own their full lattice, colours and geometry in their own module. The four generic-family reports share `generic_fixed.py`, but that module is a layout *mechanism* (pagination, header-band reconstruction, colgroup weighting) rather than a shared visual constant; each report passes its own font/pitch numbers and the emitted style blocks differ. The dismantled `TEMPLATE_CSS`/`DOC_CSS`/`document_html` funnels are asserted gone by test.

The residual fidelity gaps are represented honestly. Only `MWANZA CC SCHOOLS RANK` and `MWANZA CC SUBJECTS RANK` reach 0 logical cell mismatches; the rest carry residuals dominated by background tints and lattice-row alignment, and the pixel visible-match on page 1 spans a wide 44%–90%. Nothing in the code or docstrings claims pixel identity; the gaps are attributed to bespoke per-cell tints, un-recovered `top_schools` captions, upstream extract gaps, and antialiasing.

The hard constraints hold: reference PDFs under `data/` are untouched (empty diff), the conversion path stays 19/19 at 100%, and the test edits tightened rather than weakened the assertions.

### Page-box and page-count fidelity across all 19 reports

Page box comes from each reference's own Letter dimensions: `schools_rank.py` and `top_schools.py` hardcode the landscape box in `_document`, while `generic_fixed.PageBox` carries `PORTRAIT`/`LANDSCAPE` constants emitting the same rule. Page count is driven by recovered per-page splits rather than reflow — `schools_rank._PAGE_SPLITS`, `subject_school_rank._SINGLE_SPLITS`/`_SUBJECTWISE_PLAN`, `mock_mobility._PAGE_SPLIT`, `top_schools._BLOCKS_PER_PAGE` catalogue the exact row/block counts read off each reference PDF. The subjectwise plan is the most intricate: 18 grouped subject blocks packed onto 24 pages (plus a trailing blank the reference pads to), big subjects spanning two pages and small ones sharing a page.

The caveat worth naming: these splits are reconciled against the actually-extracted row count by `_reconcile` (and the inline logic in `schools_rank._row_splits`, `top_schools._blocks_per_page`) — underflow appends the remainder to the last page, overflow trims from the back. No row is dropped or invented, but the page-*count* guarantee is contingent on the upstream extraction matching the catalogued totals. Today they match (19/19), so reconciliation is a no-op on the real data; if `extract_data` drifts, an over/underflow could add or drop a final page silently rather than failing loudly. Content is preserved regardless (character-multiset checks), so this is a page-count robustness note, not a data-loss risk.

### Per-report independence vs the generic-family shared mechanism

The four generic-family reports (`wards_rank`, `district_performance`, `mock_mobility`, `subject_school_rank`) delegate to `generic_fixed.py`, which supplies header-band reconstruction (`_thead` rowspans shallow columns to the band depth so the header aligns cell-for-cell), semantic colgroup weighting (`_col_weight`/`_colgroup`, keyed to column *meaning* not stored width), and three pagination entry points (`render_paginated_single_section`, `render_section_per_page`, plan-driven subjectwise). The shared `_base_sheet` is parameterised by `body_pt`/`row_pt`/`banner_pt`, so emitted style blocks are distinct per report (verified: wards ≠ district ≠ mock ≠ subject) — a shared *mechanism*, not a shared *look*, with `test_no_shared_css_constant_across_report_types` asserting `TEMPLATE_CSS`/`DOC_CSS`/`document_html` are gone from `base`.

The tension: those four style blocks differ only in scalar font/pitch values around an otherwise identical rule set — "each report owns its own styling" is satisfied by parameterisation rather than authorship. If one of these four later needs a genuinely different lattice, the shared function will resist it.

### Pixel comparison for every report, with mismatches surfaced not skipped

`pixel_diff.py --all` iterates every discovered pair, rasterises reference and generated page 1 at the same matrix, and requires identical pixel dimensions before scoring. The important behavioural property is fail-loud: a size mismatch prints `DIMENSION MISMATCH: reference=... generated=...` and the report is appended to a `mismatched` list echoed at the end, and a missing PDF prints `MISSING PDF (run ...)`. Nothing is silently skipped — this is the direct answer to the user's complaint. Running it confirms all 19 clear the dimension gate and diff+overlay PNGs are written for each.

Two scope notes. Batch mode compares page 1 only (fixed `--page 1` default) — later pages of the multi-page reports are not pixel-checked in `--all`, only reachable via the single-report path with an explicit `--page`. And the exit code is driven by `exact_mismatch`, which is non-zero for essentially every report (antialiasing alone trips it), so `--all` will almost always exit non-zero; that is expected given the honest framing, but a caller wiring this into CI should key on dimension mismatch, not exit status.

### Honesty of the residual fidelity gaps

The visible-match numbers span 44%–90% on page 1. The floor cases — Mock Mobility (44.8%), the two Governments reports (44.1%) and Mwanza schools rank Overall (47.4%) — are the least faithful, and the code does not dress this up: no docstring or comment claims pixel identity. `cell_diff` reaches 0 logical mismatches only for `MWANZA CC SCHOOLS RANK` and `MWANZA CC SUBJECTS RANK` (both re-verified as 0 here); the remaining reports carry residuals the task notes attribute to background tints and lattice-row alignment, with per-page character-multiset checks proving no content is lost.

`top_schools.py` is the most explicit about its gap: the section captions above each ten-row block were never recovered into the schema, so they are reconstructed from `meta.level`/`variant`, and the docstring says so plainly. `_raster_tuned_competency` in both `schools_rank` and `top_schools` nudges four competency colours (e.g. `#00b050`→`#00b151`) to compensate for WeasyPrint's RGB-to-PDF rounding at rasterisation — a targeted, documented adjustment, not a blanket recolour, and the competency band remains the only data-derived colour (computed via `sars.competency`, never stored).

### Compare-folder naming and test integrity

The flat `output/compare/` naming that mixed `<name>`, `TEMPLATE <name>` and `PIXEL DIFF/OVERLAY TEMPLATE <name>` is replaced by three subfolders — `conversion/`, `template/`, `pixel/` — each keyed by the shared `<name> - page N` stem, with pixel appending ` - diff`/` - overlay`. Verified on disk: no flat `.jpg` remains at the compare root and no `TEMPLATE`/`PIXEL`-prefixed leftovers survive. `compare.py` and `pixel_diff.py` both document the shared-stem contract in their module docstrings.

The test edits in `tests/test_sars.py` tighten rather than weaken. `test_template_output_is_self_contained` now asserts the specific `@page{size:792pt 612pt` box for schools_rank *and* subjects_rank (previously it accepted `@page{size:A4`), so it would now catch a regression back to A4. `test_schools_rank_paints_its_own_fill_washes_and_competency_band` checks a longer, more specific list of recovered washes and the raster-tuned competency colour. No assertion was turned into a no-op or `pass`.

### Constraints re-checked

Reference PDFs under `data/` show an empty diff against `main`; `sars verify` is 19/19 at 100% text similarity, glyphs identical; `pytest` is 42 passed; `tools/cell_diff.py` is unchanged (pre-existing tooling). No renderer reads presentation from the data except the deterministic competency band.
