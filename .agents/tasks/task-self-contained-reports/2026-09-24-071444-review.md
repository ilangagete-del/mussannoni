# Self-contained per-report HTML+CSS, data stripped of presentation (v1)

The prior visual-fidelity task had baked recovered per-cell presentation (a `CellStyle` dataclass, per-row `pitch`, and `total_styles`/`total_pitch`) into `schema.py`, populated it in `extract_data.py`, and stored it in `output/data/*.json`; every templated report was then funnelled through a single shared `DOC_CSS`+`TEMPLATE_CSS` style block (with a `.report.compact{font-size:4.6pt}` clamp) and the conversion path linked one shared `output/html/styles.css`. This change reverses both: the data now carries only figures + structure, and each report type owns a complete standalone HTML document with its own inline `<style>`. Competency colour is computed deterministically at render time. The conversion path was made self-contained too (inline CSS per file, `styles.css` dropped) without changing what it renders.

Watch for: bespoke sign-conditional per-cell tints in the generic family are not repainted (mock_mobility IMEPANDA-green / UMESHUKA-red, positive/negative GPA fills) — a real visual gap, though no figures are lost (**confirmed**). The two `top_schools` reports remain lower-similarity outliers from pre-existing section-heading extraction gaps, not a regression from this change (**likely**). The `schools_rank` and generic templates hard-code their own fill-wash hex values and true point sizes as chrome — correct under DATA-IS-DATA, but it means fidelity for a report type is only as good as the hand-authored constants (**confirmed**).

**Verdict**: APPROVED

## High-level view

The data layer is genuinely clean: `CellStyle` and every `styles`/`pitch`/`total_styles`/`total_pitch` carrier is removed from `schema.py`, `extract_data.py` no longer snapshots `model.Style` or row heights, and no `output/data/*.json` file carries a single style or pitch key. JSON round-trips losslessly for what remains, and the `dict[str, list[CellStyle]]` coercion branch was removed with its only consumer.

Self-containment holds on both paths. `base.py` is reduced to primitives (masthead text, page orientation, banner lines, deterministic competency background); the shared `DOC_CSS`/`TEMPLATE_CSS`/`document_html`/`TemplatePool`/font-size clamp are gone. A new `styling.py` provides a per-document `Sheet` accumulator and a `document()` wrapper — a mechanism, not a shared look. Each report family builds its own inline `<style>` with its own class names (`table.sr`, `table.gt`, `table.sj`, `table.bs`, `table.bw`, `table.rs`). The conversion path inlines `DOC_CSS` into each file and no longer writes or links `styles.css`; 0 of the 38 output HTML files link an external stylesheet.

The cited defect (`MWANZA CC SCHOOLS RANK`) is fixed: the font-size clamp is gone so text prints at the reference size, and the template repaints the division/summary/GPA/rank washes and rotated `C/RANK`/`R/RANK` captions cell-by-cell. The competency band colour is derived, not stored.

The conversion path is behaviorally unchanged — `sars all` still reports 19/19, mean text similarity 100.00%. The remaining templated-path fidelity gaps are per-cell decorative tints that are not derivable from pure figures and are deliberately not stored.

### Data carries only figures and structure

`schema.py` drops the `CellStyle` dataclass and every presentation carrier: `StudentRow.styles`/`pitch`, `DivisionSummaryRow.styles`/`pitch`, `PerformanceRow.styles`/`pitch`, `SchoolRankRow.styles`/`pitch`, `SubjectRankRow.styles`/`pitch`, `TabularRow.styles`/`pitch`, and the report-level `total_styles`/`total_pitch` on `SchoolsRankReport`/`SubjectsRankReport`/`TabularSection`/`GenericTabularReport`. What remains is data (names, ranks, counts, GPA, competency *labels*) and structure (`column_headers` label paths, colspans, section titles, `totals` keyed by printed label).

`extract_data.py` drops the machinery that produced those carriers — `_cell_style`, `_row_styles`, `_row_pitch`, `_group_total_styles`, `_total_rows_full`, `_group_data_rows_ctx`, `_group_cols` — and the extract functions no longer thread a `Table`/row-index through to snapshot geometry. `_total_rows` now returns a plain `{label: values}` dict.

The reversal is complete in the artifacts: grepping all `output/data/*.json` for `styles`, `pitch`, `total_styles`, `total_pitch`, `background`, `size_pt`, or `CellStyle` returns nothing. `test_every_document_round_trips_through_json` still passes, so the remaining data serializes losslessly, and the removal of the `dict[str, list[CellStyle]]` coercion branch in `_coerce` is safe because nothing emits that shape anymore. `test_extracted_data_carries_no_presentation_fields` reflectively walks every schema dataclass asserting none declares a banned field and that `CellStyle` no longer exists on the module — it would fail if any carrier were reintroduced.

### base.py demoted to primitives; styling.py is a mechanism not a look

The old `base.py` was the funnel: it imported `DOC_CSS`, defined `TEMPLATE_CSS` with the `.report{font-size:6.5pt}` / `.report.compact{font-size:4.6pt}` clamp, wrapped `html_out.StylePool` in a `TemplatePool`, and `document_html` injected `DOC_CSS`+`TEMPLATE_CSS` into every report. All of that is gone. What's left is `MASTHEAD`, `orientation_for`, `banner_lines`/`banner_html`, and `competency_background` — the last computes the band colour from label then GPA via `sars.competency`, returning `None` for an unrecognised value rather than guessing.

`styling.py` supplies `Sheet` (a per-document deduping CSS accumulator), `document()` (wraps body + that document's own sheet into a standalone `<!DOCTYPE html>` with no `<link>`), `fit_scale()` (the same fit-to-A4 factor the conversion path uses, so a template can author at true recovered point sizes), and small primitives (`esc`, `rot`). `test_no_shared_css_constant_across_report_types` asserts `base` no longer has `TEMPLATE_CSS`/`DOC_CSS`/`document_html` and that two report types emit *different* style blocks — a structural guard against re-merging.

### schools_rank rebuilt to match the reference cell-by-cell

```
reference (left)            template (right)
grouped header band         grouped header band  (NUMBER OF CANDIDATES /
 + SUMMARY PERFORMANCE        DIVISION PERFORMANCE / GPA PERFORMANCE)
 washes on div groups        .bg-fmt/.bg-t/.bg-zero*/.bg-i3pct/.bg-gpa/.bg-crank/.bg-rrank
 rotated C/RANK R/RANK       rot() span, -90deg
 competency band colour      competency_background(label, gpa)  [derived]
```

`_style()` builds the whole sheet from the report's own hex constants and true point sizes (`_PT_DATA=3.98`, `_PT_ROW=6.6`, scaled by `fit_scale`), so the clamp is gone and text prints at reference size. The compare JPG confirms the fix visually: sizes, washes, structure, and rotation line up with the reference.

The total row is emitted as plain positional cells, so it depends on the body's column count matching the extracted `column_headers`. Here `_data_row` emits 39 `<td>`s (4 identity + 7 candidate + 24 division leaves + GPA + competency + 2 ranks) against 39 headers and a 39-value `TOTAL`, so it aligns — but a report type whose division-group layout (`_DIVISIONS`) drifts from its extracted headers would silently misalign the summary line, since nothing asserts the counts match.

### Generic family reproduces figures but not sign-conditional tints

`generic.py`, `subjects_rank.py`, `best_students*.py`, and `school_result_slip.py` all follow the same self-contained pattern: a private `_style(orientation[, dense])` that authors the family's own `<style>`, its own table class, its own washes, and returns via `document()`. `generic.py` adds a structure-derived density switch (`_WIDE_COLUMN_THRESHOLD=20`) that picks a smaller font for wide reports — a decision keyed to column count, not to stored presentation, so it stays within DATA-IS-DATA. `school_result_slip.py` paints its recovered pale panel (`#92cddc`) as fixed report-type chrome behind a white table.

The gap is in the generic family's per-cell decoration. In `Mwanza f2 Mock Mobility 2026` the reference paints each `MJONGEO CHANYA`/`GPA` cell green or red by the sign of the value, the `HALI YA MJONGEO` label IMEPANDA-green / UMESHUKA-red, and a green title band; the templated output reproduces every figure and the full structure but leaves those cells uncoloured. This is the documented trade-off: those tints are conditional on the value's sign and are not stored, so repainting them means the generic template would have to derive colour from the data's sign. Nothing is lost textually (`template_audit` reports mock_mobility at 99.41% with 0 lost value kinds on the figures), but it is a genuine visual divergence a reviewer should see, and it is the natural next fidelity step if the value-sign rule is deemed derivable rather than decorative.

### Conversion path made self-contained without changing render

`render_document` drops the `css_href` parameter and inlines `DOC_CSS` ahead of the per-page and pooled CSS in each file's own `<head>`; `write_document` no longer writes `styles.css`. The rendered bytes per page are otherwise unchanged, and `sars all` still reports `19/19 documents pass; mean text similarity 100.00%` with identical glyphs. `styles.css` is deleted and no output HTML links an external sheet. `test_conversion_html_is_self_contained` asserts no `<link>`/`rel="stylesheet"` and that the structural rules (`.page{position:relative`, `@page{size:A4`) are present inline.

### Test coverage

The new tests render *real* reports and assert behavior, not static values: self-containment on both paths, presence of the schools_rank fill washes plus a computed competency-band colour (`#ffff00`/`#00b050`), the absence of the shared `DOC_CSS`/`TEMPLATE_CSS`/`document_html` constants, distinct per-type style blocks, and the reflective data-has-no-presentation check. They would fail if the shared funnel or the data-side carriers were reintroduced. `pytest` is 42 passed; `ruff` and `black` clean.

Not tested: the generic family's missing sign-conditional tints have no assertion either way (consistent with them being an accepted gap); there is no test pinning the hand-authored point-size/wash constants against a report type's reference, so a constant could drift without a unit-test failure — the visual `compare.py` and `template_audit.py` are the only guards there. The `background`-substring assertion in the data test is textual and would false-fail on a future legitimate field containing that substring.
